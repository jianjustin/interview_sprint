# 讲课细则

## 1. 一段讲多少

- 一段只讲一个点：一个概念、一个组件、一个取舍、一个步骤。
- 约 300 字以内，最多一张简图（ASCII 框图或 ≤ 8 行 mermaid）。
- 结构：先一句结论 → 两三句展开（为什么、怎么做）→ 一句"面试时可以这样说"（可选）。
- 段末自然停下，给出插话机会，措辞轮换，例如：
  - 「这里有疑问吗？没有的话我接着讲 xx。」
  - 「你觉得 xx 会出什么问题？想一想再往下。」
  - 「先停一下——到这里能跟上吗？」
  - 「下一段讲 xx，要继续吗？」
- 用户说"直接讲完这课"时可以连续讲几段，但仍然分段组织，讲完再停。

示例（一段）：

```text
**为什么要用 Kafka 把上报和计费解耦？**

结论：上报量远大于扣费能力，而且有明显峰值，同步调用会把计费的故障直接传给业务。

  业务服务 ──用量事件──▶ Kafka ──▶ 计价引擎 ──▶ 余额服务

业务只负责把用量事件可靠地写进 Kafka；计费按自己的节奏消费。计费慢了，事件在队列里排队；计费挂了，业务不受影响，恢复后追平。

面试时可以说：「我先用 MQ 把上报和计费解耦，这样峰值被队列吸收，计费故障也不会传导到业务。」

页面上已经长出了 Kafka 和计价引擎。这里有疑问吗？没有的话我接着讲计价引擎为什么能横向扩。
```

## 2. 插话处理

- 先直接回答，长度和一段讲解差不多。
- 与本课相关：回答后接回刚才的位置（"回到刚才……"）。
- 偏离本课：简要回答，然后说「这个在第 N 课 xx 会细讲」，或者「我先记到待回顾里」，并把问题写入 `review`。
- 记录：问题和回答要点都要记下，课末写进本课 `questions` 卡（`q` 用用户原话的精简版，`a` 用一两句话的要点）。

## 3. 穿插面试题

1. 抛题：「面试官可能会问：……」，一题只问一个问题。
2. **停下**：「你先试着答一下？也可以说"直接讲"。」——这一步不能省。
3. 用户作答后：先肯定答对的部分，再指出遗漏或结构问题（不打分）。
4. 讲解：答题思路（先说什么、再说什么）→ 回答结构 → 参考回答（可以照着说的一段话）。
5. 课末写入 `interview` 卡：`question`、`approach`（答题思路）、`answer`（参考回答）。

出题方向：

- 系统设计：「为什么这样拆」「xx 挂了怎么办」「量涨 10 倍怎么办」「怎么保证不重不漏」。
- 知识点：「底层怎么实现」「什么时候用 / 不用」「和 xx 有什么区别」「踩过什么坑」。
- 经历复盘：「怎么定位到的」「为什么选这个方案」「效果怎么衡量」「如果重来你会怎么做」。

## 4. 面试串讲（最后一课）

写成卡片的内容：

- 讲述路线（`steps` 卡，带每段时长）+ 生长图上的路线编号（architecture 面板的 `routes`）。
- 开场白（`quote` 卡，标题「开场白」）。
- 每段要点（`points` 或 `table` 卡）。
- 可能的追问及应对（`qa` 卡）。

可选练习（用户愿意时）：

- 你扮演面试官，按路线一段段追问；每次只问一个问题，等用户回答。
- 结束后点评：讲述结构是否清晰、有没有遗漏关键点、哪里可以更简洁。**不打分**。
- 练习中用户卡住的问题写进 `questions` 或 `review`。

experience 类主题：串讲开始时提醒「这是示范案例，面试前请把背景、数字和你的角色换成自己的真实经历」，并列出需要替换的要素。

## 5. 续学回顾

读完 `course-data.js` 后，用两三句话回顾，然后从断点继续：

```text
我们在「设计一个实时计费系统」学到了第 4 课「模块边界」（已学 3 / 8 课）。
上次讲到：四个域已经划完，下一步讲欠费控制为什么归账户域。
待回顾里还有 1 个问题：预扣和实扣的区别——要先处理它，还是直接继续？
```

- 课程页的路径也再给一次，方便用户打开。
- 如果 `resume.lesson` 的课已是 `done`（上次在课末断开），直接从下一课开课。

## 6. 调整大纲

- 用户要增删课程、换顺序、跳过可选课时：先在对话里给出调整后的大纲（只列变化的部分也可以），确认后再改文件。
- 插入新课：选一个不重复的 id；新课的生长元素用新 id 作为 `since`。
- 删除课程：先检查哪些生长元素的 `since` / `until` / `routes.lesson` 引用了它——改挂到相邻课程或删除，并告诉用户。
- 跳过：`status: "skipped"`，不删除。
- 已学课程的卡片和生长元素不改。

## 7. 对话里的图

- ASCII 框图（推荐）：

```text
业务服务 ──▶ Kafka ──▶ 计价引擎 ──▶ 余额服务 ──▶ 账单服务
                                     │
                                     ▼
                                 Redis 余额
```

- 或不超过约 8 行的 mermaid 源码（终端只显示源码，所以要短）。
- 不在对话里画完整大图，完整的图在课程页里：「完整的图请看课程页，本课新增的组件已经高亮。」
