# interview-sprint 实现说明

> 这份文档是交给新会话的实现说明。读者是有经验的开发者或 coding agent，不需要回看原始讨论就能据此做出计划并实现。
> 交互样例：[docs/mockups/course-flow.html](../mockups/course-flow.html)（浏览器直接打开，可点击、可播放）。它是讨论阶段的演示稿，不是最终实现，但视觉和交互方向已被用户确认。

## 1. 意图

用户在准备技术面试（后端方向，例：设计一个实时计费系统、讲述一个 Go channel 使用场景、讲述一次 SQL 调优过程）。想要一个在 **Claude Code、Codex、pi** 三个 agent 中都能用的 skill：

- 用户给一个面试主题，agent 先理清这个主题的**重点**（非重点标「可选」），整理成一门课的大纲；
- agent 像讲师一样**逐课讲解**，穿插图示和面试题，用户随时插话提问；
- 每个主题有一个**动态 HTML 课程页**，让用户看到「课程的流动」（讲到哪了）和「系统的生长」（系统 / 代码 / 排查过程如何一步步成形）；
- 进度保存在文件里，可以跨会话、跨工具接着学。

为什么要"生长"：面试中系统是一层层讲出来的——先需求、再骨架、再边界、再非业务能力。看着系统随课程一点点长出来，用户自然形成面试时的讲述顺序。最终目标是：**懂这个主题的重点，并且能在面试里有条理地讲出来。**

## 2. 目标、非目标、反目标

**目标**

- G1 同一个 skill 包在 Claude Code、Codex、pi 中都能加载，并按同样流程工作。
- G2 开题时给出大纲：突出重点，非重点标「可选」，**不限课数**；最后一课固定为「面试串讲」。
- G3 讲课模式：agent 主讲、分段讲、每段留出插话机会；课中穿插面试题。
- G4 每个主题一个动态 HTML 课程页：课程时间线 + 生长区 + 课程卡片；agent 更新数据后页面自动刷新；双击即可离线打开。
- G5 跨会话、跨工具续学：只靠主题目录里的文件就能接上。

**非目标**

- 不产出 Markdown 笔记。md 笔记由用户自己写，agent 不生成、不维护。
- 不做以考核打分为核心的模拟面试系统（讲解为主；串讲课可以提供一轮可选的追问练习）。
- 不需要服务器、构建步骤、网络或任何运行时依赖（Node/Python 等只允许出现在开发期测试里）。
- 不做多人协作、云同步。

**反目标（技术上能跑，但算失败）**

- agent 一次输出一大篇长文，用户没有插话机会。
- 大纲把知识点平铺一遍，看不出重点。
- 课程页风格随课程、随工具、随模型漂移，或更新时丢失之前课程的内容。
- 生长区里同一组件在不同课程间位置跳动。
- 依赖某个工具独有的能力（如提问弹窗、子 agent、浏览器工具），导致其他工具跑不通。

## 3. 约束

- **Agent Skills 规范**：`name` 只能用小写字母、数字、连字符（不能以连字符开头或结尾、不能连续），≤ 64 字符；`description` ≤ 1024 字符且必须存在。因此包名定为 `interview-sprint`（不是 `interview_sprint`），目录名与 `name` 一致。
- **加载位置**：
  - Claude Code：`~/.claude/skills/<name>/`（项目级 `.claude/skills/`）。注意：本机终端里的 `claude` 是别名 `CLAUDE_CONFIG_DIR=/Users/chenjianrui/.claude-ccswitch claude`，终端 CLI 读取的是 `~/.claude-ccswitch/skills/`；桌面 App 读取 `~/.claude/skills/`。两处都要安装。
  - pi：`~/.pi/agent/skills/`，并且支持 `~/.agents/skills/`（已从 pi 1.5.0 自带文档确认）。
  - Codex：较新版本读取 `~/.agents/skills/`，旧版本读取 `~/.codex/skills/`。**实现时用本机 codex 版本核实。**
- **路径解析**：三个工具都会告诉模型 skill 所在位置。SKILL.md 中引用内置文件一律用相对 skill 目录的路径，并明确写出"skill 目录 = 本 SKILL.md 所在目录"。
- **只依赖通用能力**：读写文件 + 普通对话。可以使用 shell（三个工具都有），但流程不能依赖它才能完成（例如打开浏览器失败时只给路径）。
- **file:// 限制**：浏览器在 file:// 下不能 `fetch` 本地 JSON。数据文件必须是通过 `<script src>` 加载的 JS 文件（如 `window.INTERVIEW_COURSE = {...}`）。
- **离线自包含**：模板内联全部 CSS/JS，不引用 CDN、字体或任何外部资源。
- **终端不渲染 mermaid**：三个工具的终端都只显示 mermaid 源码。对话里的图保持简短（ASCII 框图，或不超过约 8 行的 mermaid），完整的图在课程页里看。
- **语言**：讲课和页面文字跟随用户使用的语言（该用户为简体中文）。

## 4. 方案

讨论过三种生成课程页的方式：

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A. 固定模板 + 数据文件（已选）** | skill 自带渲染器模板，开题时复制到主题目录；agent 之后只编辑 `course-data.js` | 风格跨工具/模型一致；每课改动小、省 token；离线可用；验收清晰。代价是生长区的各种形态要先在模板里实现，模板未覆盖的呈现靠一张自定义 HTML 卡片兜底 |
| B. agent 每课重写整页 HTML | SKILL.md 只描述样式 | 最灵活、无模板代码；但每课重写大文件、慢且贵，风格漂移，易丢内容，难验收 |
| C. 模板 + 每课一段 mermaid | 生长区由 mermaid 渲染 | 模型擅长 mermaid；但每次重新排版导致组件跳动，"生长"感弱；表达不了代码演进和时间线；依赖 CDN |

**用户选择 A。** 原因：核心体验"看着系统长出来"要求组件位置稳定、跨课一致，只有固定模板能稳定保证；实现交给另一个会话，A 的验收标准最清楚。架构图位置由 agent 用网格（第几列、第几行）声明，模板换算坐标，不让模型算像素。

## 5. 已确定的设计

### 5.1 开发仓库结构

当前目录 `interview_sprint/` 是开发仓库，skill 包本体是其中的 `interview-sprint/` 子目录（安装时只链接这个子目录，开发文件不会进入包）：

```text
interview_sprint/                      # 开发仓库（当前目录）
├── docs/
│   ├── specs/2026-11-03-interview-sprint-design.md   # 本文
│   └── mockups/course-flow.html       # 讨论阶段的交互样例
├── interview-sprint/                  # skill 包本体
│   ├── SKILL.md
│   ├── assets/
│   │   ├── course.html                # 单主题课程页（渲染器模板）
│   │   └── index.html                 # 多主题总览页模板
│   └── references/                    # 按需读取的细节（拆分方式由实现者定）
│       ├── data-format.md             # course-data.js 格式与示例
│       └── outline-patterns.md        # 各主题类型的大纲骨架
├── examples/                          # 三个示例主题的完整数据（验收 + 演示）
│   ├── realtime-billing/              # 系统设计：architecture 生长
│   ├── go-channel/                    # 知识点：code 生长
│   └── sql-tuning/                    # 经历复盘：timeline 生长
├── tests/
├── install.sh
└── README.md
```

### 5.2 运行时产物（用户侧）

在用户启动 agent 的当前目录下：

```text
.interview_points/
├── index.html            # 从 assets/index.html 复制，不修改
├── index-data.js         # 主题清单：只列出各主题的 slug 和目录，新增主题时才改
└── realtime-billing/     # 每个主题一个目录，slug 为英文 kebab-case
    ├── course.html       # 从 assets/course.html 复制，不修改
    └── course-data.js    # agent 唯一需要持续编辑的文件，也是进度的唯一来源
```

- agent **永远不修改**复制过来的 `course.html` / `index.html`，只编辑 `course-data.js` 和 `index-data.js`。
- 进度只存在 `course-data.js` 里；总览页通过加载各主题的 `course-data.js` 计算进度，避免两处数据不一致。
- slug 由 agent 根据主题拟定，在大纲确认时一并给用户看。
- 当前目录找不到 `.interview_points/` 而用户要求"继续"时，先问用户笔记在哪个目录，不要新建。
- 模板升级时，由用户决定是否把新模板重新复制到已有主题目录（数据格式带 `version` 字段，见 5.4）。

### 5.3 交互流程

**① 触发**

- 显式调用：Claude Code `/interview-sprint <主题>`；pi `/skill:interview-sprint <主题>`；Codex 用其 skill 调用方式（以实际版本为准）。
- 自然语言："我想准备 xx 面试"、"帮我过一下 xx"、"继续上次的计费系统"。`description` 要同时覆盖"开始新主题"和"继续已有主题"两类意图，中英文关键词都要有（面试、interview、系统设计、system design、八股、准备面试、继续学习等）。
- 无参数调用：列出 `.interview_points/` 下的主题和进度，问用户继续哪个或开新主题。

**② 开题**

1. 检查 `.interview_points/` 下是否已有相同或相近主题；有则问用户是续学还是重开。
2. 判断主题类型：`system-design`（系统设计）/ `knowledge`（知识点）/ `experience`（经历复盘）。允许混合：知识点、经历类主题在相关时也可以包含非业务能力的课（如 Go channel 的并发控制、背压）。
   - **experience 类主题（用户已决定）**：agent 自己构造一个典型的示范案例来讲，背景、现象、指标都是示范数据；不在开题时采集用户的真实经历。大纲、对话（开题时说一次，串讲课再提醒一次）和课程页上都要明确标注「示范案例，请换成你自己的经历」，避免用户在面试里照搬编出来的经历。
3. **在对话里**给出大纲：每课一行（标题 + 一句话说明本课讲什么），非重点课标「可选」；课数不限，以覆盖重点为准；最后一课固定为「面试串讲」。同时给出拟定的 slug。大纲骨架见 5.6。
4. 用户确认或调整之后，**才**创建文件：复制模板，写入 `course-data.js`（所有课程只有标题和说明，第一课为 `current`），更新 `index-data.js`。
5. 告诉用户课程页的绝对路径；能执行 shell 时尝试用系统命令打开（macOS `open`，Linux `xdg-open`），失败则只给路径。

**③ 每课讲解循环**

1. **开课**：先更新 `course-data.js`——把本课设为 `current`，写入本课的生长增量（新增的组件、连线、分组、标注、代码版本或时间线事件）。这样用户边听边看，页面就是一块白板。然后用一两句话说明本课解决什么问题、和上一课的关系。
2. **分段讲**：每段聚焦一个点，建议不超过约 300 字加至多一张简图。段末停下，给用户插话的机会（措辞自然，不要每段重复同一句话）。用户说"继续"或没有问题时讲下一段。
3. **插话处理**：回答用户问题；偏离本课的问题简要回答，并建议放到后面哪一课，或记入「待回顾」。用户问过的问题和回答要求记录，课末写入「你问过的」卡片。
4. **穿插面试题**：在合适的位置抛出"面试官可能会问：……"。先给用户尝试回答的机会（用户也可以说"直接讲"），再讲答题思路、回答结构和参考回答。大多数课至少穿插一道。
5. **进度指针**：每讲完一段，更新 `resume`（一行文字：讲到哪、下一步讲什么），保证中途断开也能接上。
6. **课末**：给出 3–5 条小结；写入本课卡片（要点、面试怎么讲、穿插过的面试题、你问过的，以及按主题需要的其他卡片），本课设为 `done`，下一课设为 `current`，更新 `resume`。告诉用户页面已更新。

**④ 面试串讲（最后一课）**

- 内容：讲述路线（在生长图上按顺序标号）、开场白、分段时长、每段要点、可能的追问及应对。
- 可选练习：用户愿意时，agent 扮演面试官按路线追问一轮，点评只针对讲述结构和遗漏点，不打分。

**⑤ 续学**

- 用户说"继续 xx"或从列表中选择主题后，agent 读取 `course-data.js`，根据已完成课程和 `resume` 用两三句话回顾，然后从断点继续。
- 不依赖会话历史，换工具也能接上。
- 如果 `review`（待回顾）里有内容，回顾时顺带提一下，问用户要不要先处理。

**⑥ 调整大纲**

- 学习中用户可以增删课程、调整顺序、跳过可选课。agent 更新 `course-data.js`，已学课程的内容和生长元素保持不变。
- 生长元素用**课程 id**（不是序号）声明在哪一课出现，插入或删除课程不会打乱已有内容。

### 5.4 数据格式：course-data.js

以下是必须支持的结构。字段名和细节可以在实现中微调，但下面列出的能力都要有，并在 `references/data-format.md` 中给出完整说明和示例。

```js
window.INTERVIEW_COURSE = {
  version: 1,
  topic: "设计一个实时计费系统",
  slug: "realtime-billing",
  type: "system-design",                 // system-design | knowledge | experience
  updatedAt: "2026-11-03T15:20:00+08:00",
  resume: { lesson: "boundaries", note: "讲完四个域的划分，下一步：欠费控制为什么归账户域" },
  review: ["预扣和实扣的区别"],          // 待回顾

  growth: [ /* 一个或多个生长面板，见下文 */ ],

  lessons: [
    {
      id: "requirements",                // 稳定 id，生长元素用它引用课程
      title: "需求澄清",
      summary: "先问清楚计什么费、多实时、量多大",
      optional: false,                   // true 时显示「可选」
      status: "done",                    // todo | current | done | skipped
      cards: [
        { type: "chips", title: "需求清单", items: ["预付费：余额不足要停服", "上报峰值 10w QPS"] },
        { type: "quote", title: "面试怎么讲", text: "我先确认几个问题：……" },
        { type: "interview", question: "预付费和后付费在架构上差别大吗？",
          approach: "先说结论，再从实时性、拦截、出账周期三点展开", answer: "……" },
        { type: "questions", items: [{ q: "预扣之后计价算错了怎么办？", a: "实扣以计价结果为准……" }] }
      ]
    }
  ]
};
```

**示范案例标记**：experience 类主题设置顶层字段 `demoCase: true`，页面据此显示「示范案例，请换成你自己的经历」提示（见 5.5）。

**生长面板（`growth[]`）**：每个面板有 `kind` 和 `title`。一个主题通常一个面板，最多建议两个（比如 SQL 调优可以同时有时间线和 SQL 代码演进）。`growth` 允许为空数组（此时页面不显示生长区，只有时间线和卡片）。所有元素用 `since`（必填）和 `until`（可选，在该课及之后消失）引用课程 id。

v1 只实现下面三种面板。偏原理、不适合写代码的知识点（如 MVCC 版本链、GC 三色标记、Redis 持久化）用 `architecture` 面板画概念框图来"生长"；时序图类面板（如 TCP 握手）不在 v1 范围内，留待后续。

- `architecture`（系统设计主题的默认形态；本质是通用的"方框 + 箭头"图，也用于知识点主题的概念图）
  - `nodes`：`{ id, label, col, row, kind }`，`kind` 取 `service | store | external | placeholder`（`placeholder` 用于第一课的"黑盒"，之后用 `until` 移除）。位置用网格坐标，模板换算像素。
  - `edges`：`{ from, to, label?, style: "solid" | "dashed" }`。
  - `groups`：`{ id, label, members: [nodeId] }`。边界框按当前课可见成员动态计算（组会随成员增加而"长大"）。
  - `annotations`：`{ node, text }`，挂在已有节点上的标注（如"分区 ×64""Lua 原子扣减"），体现能力在已有组件上的叠加。
  - `routes`：`{ lesson, steps: [nodeId] }`，串讲课在图上按顺序显示编号。
- `code`（知识点主题的默认形态）
  - `versions`：`{ id, since, label, language, code, note? }`。切换版本时，模板自动对比上一版本，高亮新增或修改的行（行级 diff 由模板计算，agent 不需要手工标注）。
- `timeline`（经历复盘主题的默认形态）
  - `events`：`{ since, title, detail?, metric?: { value, unit } }`。有指标时按数值画出相对长度的条，直观显示"3.2s → 45ms"这样的变化。
  - 可选 `metricLabel`（如"接口 P99 耗时"）。

**卡片类型（`cards[]`）**：模板必须支持以下类型。agent 根据主题和课程选择组合，不要求每课一样。

| type | 用途 |
|---|---|
| `points` | 要点列表 |
| `steps` | 有序步骤 |
| `quote` | 面试话术（可以照着说的一段话） |
| `interview` | 课中穿插的面试题：问题、答题思路、参考回答 |
| `qa` | 常见追问列表（问 → 一句话答） |
| `questions` | 你问过的（用户插话的问题和回答） |
| `table` | 表格（如模块边界划分） |
| `compare` | 方案对比（选项 + 优缺点 + 结论） |
| `chips` | 标签组（如需求清单） |
| `code` | 代码块 |
| `note` | 提示或"正在讲"类信息（醒目样式） |
| `html` | 自定义 HTML 兜底，用于模板未覆盖的呈现。不允许 `<script>` |

- 所有卡片可带 `title`（有默认标题）和 `optional: true`（显示为「可选」并弱化）。
- 文本字段支持极简行内格式：`**粗体**`、`` `代码` ``、换行。除 `html` 卡片外，文本中的 HTML 一律转义。
- 约定：每个 `done` 的课至少有「要点」和「面试怎么讲」；穿插过面试题的课有 `interview` 卡；用户插过话的课有 `questions` 卡。

### 5.5 课程页（assets/course.html）

布局与交互（参照 mockup）：

- **页头**：主题、类型、进度（已学 / 总数，可选课和跳过的课分开计）、最后更新时间。`demoCase: true` 时在页头下方显示醒目的提示条：「示范案例，请换成你自己的经历」。
- **左侧时间线**：所有课程，状态分已学、进行中、未开始、已跳过；可选课带「可选」标记；点击切换查看。未开始的课只显示标题和说明，并提示"讲到时生成"。
- **主区**：课程标题、状态、一句话说明 → 生长面板（显示到这一课为止的累计状态，本课新增的元素高亮并带出现动画）→「本课新增」标签（由模板根据 `since` 自动汇总）→ 课程卡片。
- **控制**：上一课 / 下一课、键盘 ← →、「播放生长」（从第一课依次播放到最新的进行中课程，可停止）。
- **默认视图**：打开时定位到 `resume.lesson`。
- **自动刷新**：每 2–3 秒以带时间戳查询参数的新 `<script>` 重新加载 `course-data.js`；内容有变化才重新渲染。`resume.lesson` 变了就跳到新课，否则保留用户当前查看的课。刷新时给一个轻量的"已更新"提示。
- **数据校验**：加载后校验 id 唯一、引用存在（`since`、`until`、`members`、`steps`、`resume.lesson`）、最多一个 `current` 等。有问题时在页面顶部显示可读的错误列表，并尽量渲染其余部分；脚本语法错误时也要给出提示，不能白屏。
- **架构图布局**：网格坐标换算为固定像素位置，保证同一节点跨课位置不变；连线裁剪到节点边框并带箭头；分组框按可见成员计算；标注以小标签挂在节点旁；串讲路线以编号显示。
- 浅色 / 深色模式跟随系统；窄屏单列布局。
- 在 Chrome 和 Safari 中通过 file:// 正常工作，零网络请求。

**总览页（assets/index.html）**：读取 `index-data.js` 中的主题清单，依次加载各主题的 `course-data.js`，列出主题名、类型、进度、最后更新时间和 `resume.note`，点击进入对应课程页。

### 5.6 大纲骨架（references/outline-patterns.md）

骨架只是起点，agent 根据主题增删、合并，突出重点，并把非重点标为「可选」。

- **system-design**：需求澄清 → 容量估算（可选）→ 系统架构 → 模块边界 → 核心流程与数据模型 → 非业务能力扩展：故障降级、突发流量、并发控制、可用性 / 一致性（按主题挑重点，可拆成多课）→ 可观测性（可选）→ 面试串讲。
- **knowledge**：是什么、解决什么问题 → 底层原理 → 典型场景（从一个 case 出发）→ 写法演进 → 常见坑 → 与相近方案对比（可选）→ 面试串讲。
- **experience**：背景与现象 → 定位过程 → 解决手段 → 结果与数据 → 反思与预防 → 面试串讲。

### 5.7 SKILL.md 要求

- frontmatter：`name: interview-sprint`；`description` 写清做什么、什么时候用，覆盖开题和续学两类意图，中英文触发词都要有，≤ 1024 字符。
- 正文覆盖：开题、讲课循环、穿插面试题、面试串讲、续学、调整大纲、文件操作规则（模板只复制不修改；编辑前先读；保持数据文件是合法 JS；大改动前确认）、对话里的图示规则。
- 细节（数据格式、大纲骨架）放进 `references/`，正文只说明什么时候去读。正文控制在约 300 行以内。
- 不出现任何工具专属的工具名作为必需步骤，三个工具都只靠读写文件和对话完成全流程。
- 正文用中文写；`description` 中英混合，方便三个工具路由。

### 5.8 安装

- `install.sh`：把 `interview-sprint/` 以软链接方式安装到 `~/.claude/skills/interview-sprint`、`~/.claude-ccswitch/skills/interview-sprint`（目录不存在就创建）和 `~/.agents/skills/interview-sprint`；如果核实后 Codex 版本只读 `~/.codex/skills/`，也一并链接。支持通过 `CLAUDE_CONFIG_DIR` 环境变量或参数追加 / 覆盖 Claude Code 的配置目录。
- 可重复执行；目标位置已有同名的非软链接目录时，提示并退出，不覆盖；支持 `--uninstall`。
- README 写清安装方式和三个工具中的调用方式。

## 6. 验收标准

**A. 加载**

- A1 安装后，三个工具中都能看到并调用 `interview-sprint`：Claude Code `/interview-sprint`、pi `/skill:interview-sprint`，以及 Codex 的 skill 调用方式。
- A2 frontmatter 符合 Agent Skills 规范：`name` 规则、`description` 存在且 ≤ 1024 字符，目录名与 `name` 一致。

**B. 课程页模板**（用 `examples/` 下三个示例主题验证）

- B1 双击 `course.html` 通过 file:// 打开，在 Chrome 和 Safari 中渲染正常；断网时同样可用，无任何网络请求。
- B2 architecture：同一节点在所有课程中位置不变；元素在 `since` 课出现并高亮，在 `until` 课及之后消失；分组框随成员增加而扩大；标注和串讲路线编号正确显示。
- B3 code：切换版本时新增或修改的行被高亮。
- B4 timeline：事件按课出现，指标条长度与数值成比例。
- B5 所有卡片类型都有示例且渲染正确；非 `html` 卡片中的 HTML 被转义；`html` 卡片中的 `<script>` 不执行。
- B6 页面打开时修改 `course-data.js`，5 秒内页面自动更新；`resume.lesson` 不变时保留用户当前查看的课。
- B7 数据错误（重复 id、引用不存在的课程或节点、JS 语法错误）时显示可读的错误提示，而不是白屏。
- B8 上一课 / 下一课、键盘 ← →、播放 / 停止生长都可用。
- B9 浅色和深色模式下文字和图形都清晰可读；窄屏下单列布局可用。
- B10 `index.html` 能列出多个主题及各自进度，并能点击进入。
- B11 有可重复运行的自动化检查覆盖 B2–B7 的核心逻辑（布局换算、diff 高亮、数据校验、自动刷新），方式由实现者决定。

**C. 端到端流程**（三个工具中各实际跑一遍：开题 + 至少一课 + 换工具续学）

由谁来跑：实现者在自己所在的工具里实际跑通一遍 C1–C10；另外两个工具由用户手动跑。为此交付一份逐项核对清单（如 `tests/e2e-checklist.md`）和 C9 用的哈希校验脚本。C3、C4 这类需要人判断的项，在清单里写明判断标准。

- C1 给出新主题后，agent 先在对话中给出大纲（有重点和「可选」标记，最后一课是面试串讲，附 slug）；用户确认前不创建任何文件。
- C2 确认后生成 `.interview_points/<slug>/course.html` 和 `course-data.js`，更新 `index-data.js`，并给出可打开的路径。
- C3 讲课分段进行，每段之后停下等用户插话；单段不出现长篇大论。
- C4 课中至少穿插一道面试题，并先给用户尝试回答的机会。
- C5 用户插话问的问题出现在该课的「你问过的」卡片中。
- C6 开课时页面出现本课新增的生长元素；课末卡片写入、状态变为已学、下一课变为进行中。
- C7 新开会话（换另一个工具）说"继续 <主题>"，agent 读文件后简短回顾，并从 `resume` 处继续。
- C8 中途增加或删除一课，已学课程的内容和生长图不受影响。
- C9 整个过程中主题目录里的 `course.html` 从未被修改（可用文件哈希验证）。
- C10 不使用任何工具专属的交互能力也能走完全流程。
- C11 经历复盘类主题（如"讲述一次 SQL 调优过程"）：agent 不追问用户的真实经历，直接构造示范案例；开题和串讲课的对话中提示这是示范案例；课程页显示示范案例提示条。

## 8. 讨论中我（设计者）做出的决定

以下几点不是用户明确提出的，而是讨论中由我提议、用户没有反对的，实现时可以按需调整：

- 开发仓库与 skill 包分离（包在 `interview-sprint/` 子目录）。
- v1 只做 architecture / code / timeline 三种生长面板；偏原理的知识点复用 architecture 画概念图，`growth` 可为空；时序图面板留待后续。
- 端到端验收：实现者跑自己所在的工具，另外两个工具由用户按核对清单手动跑。
- Claude Code 同时安装到 `~/.claude/skills/` 和 `~/.claude-ccswitch/skills/`（后者对应终端里的 `claude` 别名）。
